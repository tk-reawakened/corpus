# Introduction

Browse
Hi there. OC here, with my first article in this wonderful column. My goal for these articles is to show off some nifty tricks I've learned over the time I've been working with RPGCode - ranging from frequently asked questions, to more complex programming techniques. Since this is my first article in this column, I would like to leave a good impression. And, at the same time, give the reader something to think about. So let me introduce this week's subject; replacing the internal systems of the RPGToolkit. This will be a continuing series (though, they won't be released in a linear fashion), explaining how to replace some of the TK's built-in systems (such as the menu system, save/load system, and message window). Asimir, who filled in for me last week, did a fine job explaining custom message windows. As his time for writing was short, however, there are some concepts that should still be examined. So, this week's built-in system to be replaced is the Message Window (a continuation of last week. Partially because I couldn't think of anything else. I'm supposed to be full of ideas, but you get what you pay for. Hehe). Please note that I am not trying to tell people exactly how to program a custom message window. This article is here merely for the purpose of learning a few different techniques for coding them. Since Asimir already covered the basics of constructing methods, I'll just take it where he left off. I'll add in one basic feature to the message window; the ability to return the users input. Here's the example method: This custom message window is fairly simple. It takes six parameters (each one is for displaying a line of text). First, it saves the screen (I save the screen so I can clear the image and text from the screen later). Then, it runs through the process of setting the image and text on the screen. If you don't know what the concept of in-line commands is, this next line of code might be slightly confusing. All it does, really, is run the wait() command and return whatever key the user pressed. It does this by substituting the wait() command for the value it returns. So really, it's the same as writing these two lines of code: Finally, we restore the screen to its original state, and the method ends. When you want to call the method, you can return the user input just as you would with the wait() command. Here's an example: If you run that method, you'll find that there are small pauses between setting the image on the screen, and the multiple lines of text (either that or I'm just seeing things). If we could make the image and text appear simultaneously, that would make the message window look a lot nicer (in my opinion, anyway. Perhaps you enjoy the small pauses). This can be accomplished by creating a canvas, and drawing the image and text to that. A canvas, for those who aren't familiar with them, is a designated area on the screen that you can draw to. Canvases return a unique ID, which is stored in a numeric variable, and can be used as an extra parameter in all commands that have to do with drawing (i.e.: setImage, text, and drawLine). First, we save the screen (same as the first method). Next, we create a canvas, and set a background image to it. It then draws the text to the canvas. Then it draws the canvas to the screen (please note: nothing being drawn to the canvas is displayed on the screen until we use the drawCanvas() command. Hence, there are no more pauses between setting the text, etc.). All right. Now that everything is displayed on the screen, we'll wait for (and return) the user input. After returning the keypress, we kill the canvas, and the canvas ID variable, leaving us to restore the screen to what it was before the method was called. Once that happens, the method ends. The above method serves three purposes; to display text on the screen, to return user input, and to clean up after itself. However, each method should serve it's own purpose. Just like we have the mwin(), wait(), and mwincls() commands to do what needs to be done, we should be able to split this method into different parts (namely, Message() and MessageClear()). We could do this by keeping the process of saving the screen, and setting the image and text in the first method, and add the rest to the second method. This is all decided by your preference, though. Either way works fine. For the sake of presenting options, this is what the two methods would look like: This makes your custom message window a bit more like the built-in Mwin. The biggest separation from this and the internal message window is the parameter list. It is possible to make this custom message window much more like the built-in one. However, if you're using regular methods, this can get a bit messy (as it would involve global variables floating around in memory, for the current text position, one for specifying if the message window is showing or not, and possibly more). The best way to code a custom message window that mimics the built-in one is by coding a class. Since the RPGToolkit 3.0.5 hasn't been released yet (the version which supports classes), you may want to stick with the examples given. Perhaps I'll revisit the subject if ever I do an article about classes. As for now, though, I encourage that you play around with your own custom message window methods. Well, that's all for today. Keep in mind that there are many other things you could do with your own message window. For example, you could add each line character-by-character for a flashier look. Or, you could add support for profile images (which takes almost no work). I hope you enjoyed the article, and I hope you've learned something useful. As always, input is welcome, so if you have any questions, comments, or anything, feel free to express your thoughts. **Replacing the internal Systems: The Message Window**

method Message(line$, line2$, line3$, line4$, line5$, line6$) { //Save the screen for later reference saveScreen() //Create a new canvas for the message window cnvMwin! = createCanvas(640, 150) //Set the background image and text into the canvas setImage("mwin.jpg", 0, 0, 640, 150, cnvMwin!) text(2, 1, line$, cnvMwin!) text(2, 2, line2$, cnvMwin!) text(2, 3, line3$, cnvMwin!) text(2, 4, line4$, cnvMwin!) text(2, 5, line5$, cnvMwin!) text(2, 6, line6$, cnvMwin!) //Draw the canvas to the screen drawCanvas(cnvMwin!, 0, 0) //Return the keypress returnMethod(wait()) //Kill the canvas and canvas ID killCanvas(cnvMwin!) kill(cnvMwin!) //Return the screen to its original state restoreScreen() } bleah$ = Message("Hi there.", "My name is OC, and this is a message window.", "", "", "", "")
