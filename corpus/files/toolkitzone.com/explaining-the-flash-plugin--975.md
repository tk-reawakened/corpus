# Explaining the Flash Plugin

A useful document to accompany Truiken's flash plugin, which was rather devoid of examples. Although you will still need the flash plugin's included readme to understand most of the plugin's power, this tutorial explains the basics of the plugin in nice and simple terms, as well as providing an example for the more hands-on coders.
> Tutorial By: SolaceinSilence Explaining the Flash Plugin - Version 1.0
>
FLASH, its everywhere today on the web. It's used for a multitude of things, from simple effects to add visual pleasure to a page, to games, and even complete websites. This is by far (in my opinion) the most popular way to convey creativity on the world wide web. So it's only natural for such a promising piece of software such as the Toolkit to have Flash intergrated into the games it produces. The idea is a great one indeed, and many thanks goes to Triuken for creating the Plugin. Ok well now that all of that is out of the way, we can jump right into the tutorial finally. So you've downloaded the Flash plugin, installed it and have this great idea for flash intergration. Maybe a cool Battle System, or even better a Flash Menu! Oh wait, you've got it flash cinematic scenes! It's all coming together in your brain but then suddenly you realize, you don't know how to use the plugin. Wait! There is a readme file that came with it. So you open it and stare at the screen blankly for several minutes. Well, erm... At least its a complete documentation? I have to hand it to Triuken he did do a good job documenting the commands, but the examples are rather poor.
Ok well lets say you have created this cool little flash animation that shows the title of your game. You want Trans to play the flash file then take it away once it is over. Simple enough, right? Right. Before we start coding this, let write some pseudocode for it. Pseudocode becomes a great help whenever you write larger programs. Pseudocode is basically plain English that describes the program flow, without using any specific syntax from the program language. If you have learned any other programming languages, you may be fimilar with pseudocode. Many consider it good programming skills to have pseudocode, before you actually have the program created. It's also considered good programming skills whenever you put pseudocode at the beginning of your program, just so that others that see you program can have a generlized idea of what it does. Of course, its up to you wether or not you want to use pseudocode, but for simplicity purposes, this tutorial will contain it.
pseudocode:
*********************************************************** * First, we want to set the flash movie to a number in memory. * Then we want to specify all other attributes of the movie * * We want the trans to listen to the flash movie for fscommands * We want to create some variables for a loop and a check * * Ok, so we need to * Loop While(a variable is equal to, say, one) * * Inside the loop we need a IF Statement * to check if the movie is over * if it is, first remove the movie * then make the loop variable equal 0 so * that the loop will expire. * Then we need to Kill() the varibles we created to free up memory ***********************************************************
rpgcode:
#SetFlashMovie(0, "mymovie.swf",0,0,640,480) #swfFSCommand[0]$="auto" MovieOnScreen! = 1 EndMovie! = 0 While(MovieOnScreen! == 1) { If(#EndMovie! == 1) { #SWF_Remove(0) MovieOnScreen! = 0 } } #Kill(MovieOnScreen!) #Kill(#EndMovie!)
As you can see, we have written pseudocode, and a program. Now in case you still are a little bit confused about what is going on, I will explain the RPGCode. Lets take a look at the first command , it follows this syntax this is the most important command when using Flash, because this sets the Flash Movie onto your board, or in a program. The first parameter, refers to the slot in memory that your movie exists in. You can have up to 10 flash movies in memory (0-9). It is very important that you set a slot for your movie, and remember it, because it will be how you call the movie from that point forward. The next parameter, is a literal variable where you specify the filename of your movie. Before I go any further, let me mention that ALL of your Flash Files must be put into your folder inside of your Game folder. This is where Trans looks for the Flash Files and if you do not put it in the folder, then you will get an run-time error. The next two parameters, are numeric numbers that represent your x and y coordinates in your game. Be sure to enter the pixel value for these. The last two parameters, specify the width and the height of your movie. Again these are in pixels. #SetFlashMovie(0, "mymovie.swf",0,0,640,480) #SetFlashMovie( slot!, filename$, x!, y!, width!, height! ) slot! filename$ **Misc** x!, y! width!, height!
The next command, , is the next most important command. It allows Trans to listen to the Flash Movie. Why is this important? Well as you saw in our rpgcode example, I created an IF() statement inside of the loop the check to see if the variable was equal to one. If it was it would remove the movie from memory and stop the Loop. This brings me to my next point. Inside of your Flash Movie, you need to use something called an FSCommand. The FSCommand allows you to send data from the Flash Movie to Trans, thus allowing Trans and Flash to communicate. This is how you are able to remove the Flash Movie from your board, program, and memory. At the last frame of your movie (or where ever you want it to be), you insert and FSCommand that looks similar to this: . So when the Flash movie reaches that frame, it executes the FSCommand, sends the variable to Trans, Trans then sets the variable assignment, allowing for the IF() statement to become true, thus allowing for the Movie to be removed from memory, and causing the Loop to expire. Cool huh? With the use of FSCommands, you can create a whole range of different interactive movies. From custom Battlesystems, to interactive Menus, to anything else you can think of. #swfFSCommand[0]$="auto" #EndMovie! FSCommand(#EndMovie! = 1)
These next two variables are for a Loop, and a IF() statement. We need a loop because we need Trans to constantly check to see if out movie is on the screen and to see if the flash movie is over. That is why I have a IF()statement inside of the Loop. The Loop is checking the IF() statement, over and over until the varible becomes something else. As I just explained the FScommand() allows for the variable to be changed once the Flash Movie hits a certain frame. The last two RPGCode commands, are used to remove the variables we created from memory. This is important because, if you do not remove the variables they can build up and cause the program to crash.
