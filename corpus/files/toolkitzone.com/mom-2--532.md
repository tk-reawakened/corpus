Explains __\___\__ _____ _____ \ \ \ \___ ___\___\_ \ \ \ \ __\_ _\_ ****
The #If command is probably one of the best commands in the TK. With it, you are able to steer the game any way you want it to. The #If command is the main of systems, conversations, places to visit, magic to learn, and many many more so understanding it would be a great asset to any game.
by TKGB >>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>What is #If?
An #If command is similar to other if commands out there in the programming world. Just like in real life, it asks if something is true. Example:
"If I was king, I would have a monkey as a pet."
Quote taken from cbm. The sentence states that if I was king of the world I would have a monkey but since this isn't true, I don't have a monkey as a pet.
>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>How does an #If command work?
The #If command is writtend like this:
**** #If (variable!==value) {block}
-or-
#If (variable!==value) {
**** When it is accessed, it detects the variable (a variable is always used to determine what is to be detected) and see if it ajasent with the value. Then if it's true, the block is then accessed. If you don't understand it then keep reading for more detailed info.
>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>Variables
Two kinds of variables exist: Literal and numerical. I highly suggest using numerical for minial task but literal can be used to detect words. Such as if we wanted to know who was who and give them an amount of HP, you would write this:
**** #If (playerHandle[0]$=="John") {#GiveHP(10)}
**** This is no different from variables. There is no extra neccesary requirement for the #If command to work. Like a variable, you just write it down with the value and presto, the #If command will read it.
The block (in this case #GiveHP(10)) is where all the commands go in for the #If command to detect so its no different from writting a program.
>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>Variables and commands
As you know, variables can be created but there are some commands that have variables as their source like #GetHP(), #GetGP(), #Wait(), and others. Though nothing different from above, you just do regularly like you would with variables you created. Just don't use the entire command like this:
**** #If (#GetHP("John",John[hp]!)=0) {John[hp]!==John[maxhp]!}
**** Instead do this:
**** #If (John[hp]!==0) {John[hp]!==John[maxhp]!}
**** >>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>Going places
Now as you know, a game changes based on actions done to it. Like say we have John go to a house and talks to his mom and she says:
"Dear son, do take this money with you."
and if you talk to her again she says:
"Come back early."
How do we do that. Well the #If command can do it and under a minute. In a .prg file you would write:
**** #Mwin("Dear son, do take this money with you") #Wait() #MwinCls() #GiveGP(100) #End()
**** This is for the first part of the conversation. Now how about we go and make the program to say the other thing when you talk to her.
**** #If (mom!==0) { #Mwin("Dear son, do take this money with you") #Wait() #MwinCls() #GiveGP(100) #mom!==1 #End() } #If (mom!==1) { #Mwin("Come back early.") #Wait() #MwinCls() }
****
Ok now the program goes that if variable mom! equals 0, she will say something, waht for the player to press something, clear the message window, give you 100 gp, and set the variable mom! to 1. Now notice the varible has changed. Now the variable is set to 1 and will never change unless you tell it to anytime you wish. Now when we talk to his mom again, the program will read if mom! equals 0, but this time it will detect that it does not so it will skip all of the block and go to the next command which is another #If, and this one has mom! equalling 1 so now John's mom will say the next thing and since there is no variable called mom, it will say that everytime.
Go that? Good. now lets see this little doozy.
**** #If (mom!==0) { #Mwin("Dear son, do take this money with you") #Wait() #MwinCls() #GiveGP(100) #mom!==2 #End() } #If (mom!==1) { #Mwin("Come back early.") #Wait() #MwinCls() } ****
Notice anything different? Well look at the variable that was suppose to change mom! to 1. It now equals to. Well what happens now? Nothing. Thats right. Since both the #If commands do not equal 2, then the program will skip them, and since there is nothing else to read, the program quits. Simple. Now lets look at this tibit:
****
#If (mom!==0) { #Mwin("Dear son, do take this money with you") #Wait() #MwinCls() #GiveGP(100) #mom!==1 #End() } #If (mom!==1) { #Mwin("Come back early.") #Wait() #MwinCls() } #If (defeated_boss!==1) { #Mwin("Hello son. Welcome back.") #Mwin("Are you hungry?") #Wait() #MwinCls() } **** Now what is this? A third #If command with blocks and this time the variable is called defeated_boss!. But we don't have one called defeated_boss!. Not yet anyways. What do I mean? Well its simple. Since it is not created, the value is automatically 0. If it is never declared then it will always be 0. Hence the name, we assume that the variable will be 1 when a certain boss is dead and therefore it will never be accessed until that boss is defeated (when the boss is defeated, it is assumed that the program will have a variable called defeated_boss! along with the value 1).
So is John hungry? We don't know do we. Oh thats right, we are supposedly John so we got to answer the question. How? Here's how:
****
#If (mom!==0) { #Mwin("Dear son, do take this money with you") #Wait() #MwinCls() #GiveGP(100) #mom!==1 #End() } #If (mom!==1) { #Mwin("Come back early.") #Wait() #MwinCls() } #If (defeated_boss!==1) { #eat!==0 #While (eat!~=1) { #MwinCls() #Mwin("Hello son. Welcome back.") #Mwin("Are you hungry?") #Wait(button$) #If (button$=="Y") { #Mwin("Sit down and I will get you lunch.") #Wait() #MwinCls() #sitinchair!==1 #eat!==1 } #If (button$=="N") { #Mwin("Ok then.") #Wait() #MwinCls() #eat!==1 } } } **** THE PROGRAM GREW!!!! Not really, its still the simple #If command.
So first lets see the block where he eats. Notice the #While command. This command works like #If but differently but I will not go into it in this tutorial. Notice the #Wait command. It has a variable called button$. The #Wait command can hold a variable used to detect the letter pressed but whether the program does what you want with it is up to the #If command. Ok after the #Wait command, there are two #If's now with literal value's. The values are the letters that are available, in this case 'N' and 'Y' are used. When you press the right letter, the block will be triggered with the appropriate commands. So if you press N, mom will tell you "Ok. then". If you press Y, then she will ask you to take a seat. Notice another variable. sitinchair!==1. This variable is used for the chair and since the program is about taking a seat, it is assumed that 1 is the magic number that will allow your character to take a seat.
This program is all nice is smooth except one thing: since mom! still equals 1, then the block with mom!==1 will still run and we just want John to be asked for lunch. So what can we do? Nothing to it. In the other .prg (the one where you defeat the boss) just write down
**** #mom!==2 ****
Remember what I said about it being equal other than 0 or 1? Well now that there is more for it to read, it will run the block that is dependant on defeated_boss!.
>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>Apply Knowldege
**** #If (mom!==0) { #Mwin("Dear son, do take this money with you") #Wait() #MwinCls() #GiveGP(100) #mom!==1 #End() } #If (mom!==1) { #Mwin("Come back early.") #Wait() #MwinCls() } #If (defeated_boss!==1) { #eat!==0 #While (eat!~=1) { #MwinCls() #Mwin("Hello son. Welcome back.") #Mwin("Are you hungry?") #Wait(button$) #If (button$=="Y") { #Mwin("Sit down and I will get you lunch.") #Wait() #MwinCls() #sitinchair!==1 #eat!==1 } #If (button$=="N") { #Mwin("Ok then.") #Wait() #MwinCls() #eat!==1 } } }
****
When mom!==0, then the first block is triggered. When mom!==1, then the second block is triggered. If mom! doesnt equal 0 or 1 then nothing is triggered unless defeated_boss! equals one, in which case that block is activated. When it is then it will ask you if you want lunch. If you type yes then you will be asked to take a seat. If you press N, the "Ok then." will be said.
Also remember that variables must be before the #End() command.
