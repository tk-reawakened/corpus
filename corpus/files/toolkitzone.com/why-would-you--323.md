# Why would you?

What makes the RPG Toolkit such a great and flexible game maker rests almost entirely on the shoulders of RPG Code. RPG Code can do virtually anything, although trying to do extremely advanced programs will run very slow. However, for writing simple RPG related programs like battle systems, message windows, etc RPG Code is perhaps one of the most versatile scripting languages available. Although technically RPG Code is a scripting language, its power can be matched up to that of an actual programming language. For those of you not acquainted with how programming works, and you're not sure whether or not you want to learn RPG Code, then I'll take you through it. Programming is evil! Programming deadlines keep you up at night! Programming will make you miss important meetings! Programming is the last place you want to be! If you think the above statements are jokes, then you're probably not a programmer (or not a good programmer). I assure you that the above are true, and if you really want to continue, well then read on. So why would you want to learn a programming language anyway? Well the answer is simple, if you don't have a person to make programs for you, then you'll probably need to learn some programming. Unless you plan on making an RPG with the Toolkit without any knowledge of RPG Code (which means no talking NPCs, no cool graphics, no customization) then your game WILL suck (I'm sorry if I'm being too soft, but it will). So then the questions would be, learn the basics? or memorize the command reference? (not the questions you were thinking of... didn't think so, just shut up and read). Well, if we take the latter question from the above and answer it, what would happen? Well okay, so you've memorized the whole command reference, now what? Exactly, you can't do anything. To learn how to program is to learn another language. If you went ahead and memorized every word in the Spanish dictionary, how would you make a sentence, how can you talk to the person? Same thing goes if you memorize the command reference. How can you 'talk' to the compiler? The only thing you would be able to do is understand what people are saying, and not say it yourself. Unless that's your goal, read on. Programming is learning (not memorizing) a command, and being able to apply it within your game. With some commands that can be an easy task, but with others, it can really be shitty. What does this mean? Well it means that MrG over there at RPG Code Shack not only knows every single command in RPG Code, he knows how to use every command. But that's still not enough, programming is much more. So what else does MrG know? He knows how to use them effectively, and apply those commands, and manipulate them to do his bidding. This is sort of like what he can do with newbies in the community (but doesn't). For example, "Um yeah to display text you would have to put youradumbass("Text goes here")" Why he doesn't do this is probably because he's sympathetic (it's a weakness I swear!). But he might just not waste his time with stupid questions like these and wait for others to pick up the question. RPG Code only has 80 commands (and one of them has the ability to make more). That makes it an easy language to learn, in comparison to C++ (or FORTRAN :P). So learning it won't be too difficult, just make sure you have a firm understanding of high school algebra and you'll be fine (if you don't have that understanding, it's still pretty easy so don't run off just yet). You've decided to take the plunge? Well, without further ado, here are some simple RPG Code commands that I will teach you. These commands will must likely be in your game, so you might as well attempt to listen. Well, probably the easiest part of RPG Code is displaying text. And if you want anyone talking in your game, then you might as well learn this! The command for displaying text is simply #MWin("..."). Note that the symbol '#' must be placed before all commands in RPG Code (except @, but that's not really a command). Now what does this command mean? Well I'm guessing that the 'M' stands for message, and 'win' stands for window (therefore message window). So that's you talking to the compiler (a compiler is basically what listens to you and tells the computer what to do in yet another language called machine instructions. You do not have to learn that) and telling it to open a message window. So then what's the deal with those brackets? Well the brackets are what's going to hold the text value. The text value is basically what you want to say in English (or French, or whatever). So to say what you want simply put quotations around it and say it! Here's an example: #MWin("I like to eat chocolate while taking a shit") So I said what I wanted to within the quotations, and told the compiler to say it. Wow, that wasn't so hard! But wait a minute, if you tried to compile (also known as run) that program, the text would flash and you wouldn't be able to read it. "What the fuck! Piece of shit computer!" Actually, it's not entirely the computer's fault. The reason being is that the computer is stupid. "What! Madness! The computer is the best invention known to man, why just look at the games I can play!" Well the computer doesn't know how to run those games unless someone took the time to write up everything and tell the computer what to do. Very tedious. So in the above example, we also have to tell the computer to wait for the user (that's the player) to press a key before it 'disappears'. So here's how we do it. #MWin("I like to eat chocolate while taking a shit") #Wait(a$) What did we learn here? Well since this programming language was made with ease-of-use in mind, I think we can all guess what #Wait means. "But wait a minute, what the hell is that? That, thing there." That thing you're referring to is yet another value. This value is basically any key on the keyboard. The compiler now knows that he's suppose to wait (hence #Wait) until someone pushes a key. Well tada! That's how you display text! Before I go on here are a few things you should know. If you write all your text in one #MWin, it won't go on to the next line (again, stupid compiler). So you have to create another MWin once you think it's finished. For example: #MWin("This is the first line of text") #MWin("And this is the second") #Wait(a$) Also, the text box where your text is shown is only a certain size. You'll find that you have to erase everything and then put different text on. To do this you simply add this command #MWinCls(). This clears the text box allowing other text to be put on. For example #MWin("You worthless piece of shit, can't you do anything right!") #Wait(a$) #MwinCls() #Wait(a$) #MWin("How dare you try to shut me up!") This is very simple. Basically, if you want to go back to your code, and don't understand what the hell you did commenting will save you. What is commenting? Well basically you display plain old English and tell the compiler to ignore it. To do this, you use an *. Here's an example: #MWin("lalala") *look! I can talk to myself! I'm a genius! #Wait(a$) As you can see if you run this program, everything that's after the star on that line is ignored by the compiler. In other words your telling the compiler "Skip this part and go on to the next". The If statement is another function that performs a loop. "A loop, wait a minute, I heard about these things. Oh no, you're not getting me into one of those things!". Actually loops can be quite easy. Just read on and you'll find out. Other tutorials might try and say this: "The If statement is where you test if one value is true or false, and then if it is true you do this, and if it is false you do this." My first impression of that description was, "What the fuck do I look like, a genius, what the hell do you mean bitch!" So I'm going to try and make this easier for you people. What I'm telling the compiler to do is to look and see if something is right. If it is not right, then I tell the compiler to do a certain thing, if it is right then I tell the compiler to do an entirely different thing. Since this probably still makes no sense, let's take a look at an example: #MWinCls() #MWin("What do you think about this tutorial?") #Mwin(" 1- It's awesome!") #MWin(" 2- It sucks!") #Wait(result$) #If (result$=="1") { #MWin("Right on brother!") #Wait(a$) } #If (result$=="2") { #MWin("Shut up ass hole!") #Wait(a$) } Wow, that's a lot of new shit just in that one program. Don't worry, I'll hold your hand once again and tell you what everything means. First of all, you already know the beginning part where it asks what you think of this tutorial. But wait, why is 'result$' in the brackets for #Wait, instead of (a$). Well result$ is simply what the player pressed saved into the compilers memory (I did say computers are stupid, but they can still remember shit). So when I say #Wait(result$) I'm telling the compiler to wait for the user to press something, and then remember what he pressed. So then we continue. The next thing you see is the #If() function. Now guess what I'm telling the compiler in this line: #If(result$=="1") { #MWin("Right on brother!") #Wait(a$) } Well if you hadn't guessed, it's simply telling the compiler to remember what the player pressed. If it is "1" then tell him "Right on brother!". But what are those... those curly braces (the { and } are called curly braces). The curly braces tell the computer, "Okay so the answer is 1, then { means begin what to do here, and the } tells the compiler to stop what its doing". Therefore if the result was 1 the compiler would only look at what's inside the { } and ignore the stuff that's outside of it. Now if the result wasn't 1, then the computer goes to the next If statement and sees that it's 2 and then runs the other #MWin. In any program that's more advanced than simple little #MWin's, you're going to need variables. In this tutorial I'll teach you what the hell they are, why do you need them, naming them, and how cookies and cream can make you feel alive. Variables are used in programs to store information. In almost all programs, you're going to need to store some kind of information. Even in a simple MWin program, when you add the #Wait(a$), a$ is a variable. The computer can remember a lot of different things, but you have to tell it what to remember. Variables do just that! As far as I know, variables are used in every single program you make. So learning about them is a good start (hint hint). Now before running away screaming because you remembered your old high school algebra teacher, come back! I'm not going to bore you with what ever the hell your teacher did. I'm a person just like you, not a teacher. Okay, so now I'm going to teach you silly creatures how to declare variables. In RPG Code, it's *very* easy. So let's declare a variable, and give it a value: #cheese!=21 Okay, so what did we see here? Well, we started the program with a '#'. This has to be put before everything in RPG Code (except @). Then we gave it a name, 'cheese'. That was simple enough. Now, who knows what '!=' is? Well, ! is put after every numeric variable. What do I mean by that? Well numeric means numbers. So therefore, when I say '#cheese!' I'm telling the computer, "Make a variable called 'cheese' and make it numeric so that it can hold numbers." I think it's pretty obvious what the = sign does. It makes cheese! have the value 21. The = sign does not mean 'equal to'! So now we have a variable that is numeric, and has the value 21. So what? Well, now we can manipulate it. #cheese!=21 #cheese!=cheese!+3 Now, if this was math, what I just did is completely wrong. But this is not math. So let's look at why it's not wrong. cheese is 21, right? Okay, that's what I told the compiler first. Then I told the compiler that cheese now has the value of cheese plus three. Therefore, that makes cheese have the value 24 (because 21+3=24). Now these variables are useless, because there is no point to this program. But now you know how to use variables in your programs! Hurrah! But wait... there's more (don'y cry, please?). The above variable was numeric. What if I wanted a variable to hold text and numbers? Well, you would change a few things. Let's take a look at some sample code: #hello$="Hi, you suck!" The first change we see here (besides the change in the variables name) is that ! has been replaced with $. Just as ! meant numeric, $ means that it can store everything from numbers, to characters from your keyboard. The next thing you'll notice is that 'Hi, you suck' is in quotation marks (""). This is because, since this is a text value, we have to save it as one. Okay, so there you go. You now know how to use variables! Go, and run free young one! Learning RPG Code
