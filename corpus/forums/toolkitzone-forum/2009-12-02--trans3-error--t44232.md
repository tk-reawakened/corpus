**Engine Bugs - Report &amp; Discuss**

This issue has been resolved.
OC, thanks for the reference on the inheritance bug. I can confirm that it behaves exactly as described in that post. Here is what I have deduced so far:
When a program is included, all of the machine units from methods contained within the program being included are copied to the currently-loaded program. During this process, all of the method and class definitions are also copied over.
The problem is likely occurring when the classes are copied; class descriptors contain a methods container which contains references to all methods contained within a class definition. The problem is, each method in that container has a reference to the first machine unit that constitutes the method statement block.
Basically, what seems to be happening is that this machine unit reference variable is not adjusted to match it's new position, after being copied to the current program... so it's referencing it's old position.
Take a look at the following example(s):
ExampleB.prg

**Code:**

```
class B

{

public:

 function B()

 {

  y = 200;

 }

 function testSubclass()

 {

  mwin("[Subclass] Value: " + y);

  wait();

  mwincls();

 }

private:

 var y;

}
```

ExampleA.prg

**Code:**

```
include("ExampleB.prg");

class A: B

{

public:

 function A()

 {

   x = 100;

 }

 function testParent()

 {

  mwin("[Parent] Value: " + x);

  wait();

  mwincls();

 }

private:

 var x;

}

test = A();

test->testParent();

test->testSubclass();
```

When ExampleA.prg is executed, the result is very interesting. Instead of showing the expected:

**Code:**

```
[Parent] Value: 100

[Subclass] Value: 200
```

You get the following output:

**Code:**

```
[Parent] Value: 100

[Parent] Value: 100
```

This occurs because both programs have almost exactly identical instruction units... so when class B is included, it's machine units for the testSubclass function are actually pointing to the machine units for class A's testParent function, because the machine unit references for the methods contained within class B were never adjusted.
That's basically what I have discovered so far, but I am not sure that is actually the reason class inheritance is broken. It seems to be the case at the moment, though.
