# Different basic languages...

### Levi · 2004-08-01 20:25 · #B68480

For those of you who love Basic languages I'd like to start a list.
QB
VB
Liberty B
Rapid-Q(production haulted but a great community of users)
FBSL(Free Basic Scripting Language)
Real Basic
I do VB QB LB and RQB, I'm learning FBSL but it's not as structured as the others. It's a scripting lanuage with many extras, including direct access to the windows API, this however requires alot more programing and knowledge of how to use it.
Rapid Q is good but as I've said the creator stopped its production, its still free and you can sell what you make but it is limited. Although you can do a limited access to Windows API's and use DLL's to help in its creation. It's source code was sold to make the RealBasic compiler. Not the greatest but it's not bad. Liberty Basic is also good for making programs but it doesn't have the ability to make EXE's. And VB is okay but expensive I use it as more of a building block to use with other languages.
QB is also a building block, it allows the the testing of algorithms and data manipulation, everythign visual is then tested in VB and then converted to another language. Qb is a great place to start learning programming but is small in what it offers alone. Of course mix it with ASM and that is one powerful sucker.

Damn, that would totally beat the hell out of my old Tandy. ;) It didn't have a harddrive and it only had 64kb of RAM. The 5 1/4 floppy drive used a harddisk controller plugged into the side of the computer with an exposed IDE cable. Didn't have DOS, just a command interpreter for a command line. More fun than just about any other computer I've owned, though. I think people who haven't used older computers much need to play around with older ones to see just how far things have come and get some respect for old systems.
What's the big deal with a 'real' programming language, though? The line's blurred, especially with languages that aren't sandboxed inside of an environment. Speed doesn't matter so much anymore (who here has a processor faster than 700 Mhz? 1GHz? 2Ghz?). Neither does memory footprint from running an interpreter and interpreting the program (who has more than 128 megabytes of RAM?). And, with an interpreted language, you don't have to compile your program, which is a big plus. You speed up development time immensely, and it's easier to work with other platforms (if your program is platform independent) since you don't have to compile binaries for each platform.
