# Is it possible?

### Zorch · 2005-03-10 08:36 · #B178501

I have a very specific idea on how I want the battle system in my game to work, and I just wanted to know if it was within the abilities of the toolkit before I even bothered.
Essentially its tactical, meaning monsters and characters moving around and having to close in on each other before attacking. It will all be in real-time, characters will silmutaniously fill up an initative bar based on the sort of attack, the weight of the weapon, morale, and injury. It will be pauseable at any time to issue commands. There will be no HP system, damage is done to parts of the body, injury will judge if a character is incapacitated, and bleeding and blood loss will judge if a character dies. It is possible that a monster and a character hit each other simultainously (optional).
Many stats affect a characters combat proformance in the battle system:
Standard stats(agi, str, int, and so on).
Armour/shield.
Magical enchantments.
Burden of inventory/armour.
Injury.
Morale (If not the lead character).
Type of weapon used (Slashing, Piercing, Bashing).
Skill with weapon and/or shield.
Weight of weapon.
Favour with the Gods.
Other combat skills (fencing, pugilism, preception, dodge, leadership)
So, what'cha say? Smile

It is possible with the TK. Only it is difficult.

### Allan@Aljo · 2005-03-13 00:42 · #B179723

what you do is you use threads... read up on them. Very Very possible. It will be slow a bit but also there is a technique for speed coding in RPGCode that involves If's and the way you put in methods and stuff...
basically to speed code... I'm going to use part of my code...

**Code:**

```
Method Level::IsSolid(x!,y!)

{

   dest$=mid(this->levelshard[x!]$,y!,1)

   if(dest$~=".")

   {

   stlength!=length(this->solidtiles$)

   for(i!=1;i!<=stlength!;i!=i!+1)

   {

      dest2$=mid(this->solidtiles$,i!,1)

      if(dest$==dest2$)

      {

         returnmethod(i!)

         i!=stlength!+1

      }

      if(dest$=="M")

      {

         startx!=x!

         starty!=y!

      }

   }

   }

}
```

Ok what this code is for is unimportant but the original version look something like this

**Code:**

```

{

   dest$=mid(this->levelshard[x!]$,y!,1)

   stlength!=length(this->solidtiles$)

   {

   }
```

Two key lines are missing in the original
if(dest$~=".") and
i!=stlength!+1
In my file format for my Level in Goomba I know that I will always make "." my air. So why process all that other crap when the part of the map I"m looking at is a ".". The second line is in my for loop. My level is loaded by shards. so a part of the level may look like "L........." and I load what letters will be solid in solidtiles$ which looks like this "LB". the forloop checks to see if "L" is in "LB" and if it finds a match it returns the position in "LB" it is, but then it goes ahead and checks to see if L is == to B as well. so I make it stop when it first finds the solid it's looking for using the second line. That is what I mean by speed coding... always look for ways to by pass chunks of code to make it run faster. The best way is with If's where it don't always need to run.
