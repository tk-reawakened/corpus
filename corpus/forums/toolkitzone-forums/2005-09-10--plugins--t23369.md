### Colin · 2005-09-10 16:53 · #B256009

A DLL is just a binary that can be mapped into an application's call space at runtime. (Dynamically linked library.) This will be what you get after your project is compiled and linked. Note, however, that plugins do not need to be DLLs. In theory, they could also be OCXs and ActiveX EXEs, though DLLs certainly make the most sense of the lot.
If you want to make a VB6 plugin, you'll need VB6. (This program is not free of cost.) The vbp file is the Visual Basic Project file. Opening it will open the whole project in the Visual Basic environment for you to work on.

### Colin · 2005-09-10 17:09 · #B256022

Maybe I didn't explain well enough. A DLL is a binaryit's something you get after you build your project.
When you're making a plugin, you do not modify DLLs; you work on your plugin's source, and when you compile the source, the result is a DLL. The vbp is a Visual Basic Project file. It's like a main game file for Visual Basic. If you open it, you'll be able to work on a VB plugin. I think the problem is that you don't own Visual Basic 6. This is not a free program, and it is required to work on a VB plugin.
The case is exactly the same for the C++ plugin SDK, save that the project file is a dsw and that Visual C++ 6 is the program you need.
