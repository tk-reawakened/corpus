# Funky item creation deal

### zyrshnikashnu · 2006-02-03 03:02 · #B294640

I'm having some strange issues when placing items that didn't exist in TK2. Let's say I've got something along these lines:

**Code:**

```
createItem ( "enemy1.itm", ene1! )

putItem ( ene1!, 11, 13, 1 )

createItem ( "enemy2.itm", ene2! )

putItem ( ene2!, 22, 16, 1 )

createItem ( "enemy3.itm", ene3! )

putItem ( ene3!, 15, 10, 1 )
```

When this is executed, I can see each that each of the items is placed, but its as if they're occupying the same slot. I though, OK, I'll just make sure they're in different slots. So I implemented something like this:

**Code:**

```
createItem ( "enemy1.itm", ene1! )

putItem ( ene1!, 11, 13, 1 )

ene2! = ene1! + 1

createItem ( "enemy2.itm", ene2! )

putItem ( ene2!, 22, 16, 1 )

ene3! = ene2! + 1

createItem ( "enemy3.itm", ene3! )

putItem ( ene3!, 15, 10, 1 )
```

In this situation, however, only items 1 and 2 appear, and 3 is nowhere to be seen.
Finally, I tried one last thing:

**Code:**

```
ene1! = 0

createItem ( "enemy1.itm", ene1! )

putItem ( ene1!, 11, 13, 1 )

ene2! = ene1! + 1

createItem ( "enemy2.itm", ene2! )

putItem ( ene2!, 22, 16, 1 )

ene3! = ene2! + 1

createItem ( "enemy3.itm", ene3! )

putItem ( ene3!, 15, 10, 1 )
```

In this case, only item 2 showed up. This seems to be extremely inconsistent on the TK's part.

### Colin · 2006-02-03 14:26 · #B294724

"silly createItem()" is quite a good description. If you read the manual, you'll learn that you're supposed to put a number that the item will be created into. (An "accidental" change on my part.) If you put an empty variable, they will all be created into slot zero. In 3.0.7, createItem() will work both ways, so that code will work. In the meantime, you can change it to use ordinal numbers, and that will still work in 3.0.7.
If you still can't get it to work, which some people claim not to be able to (I haven't tested extensively myself), everybody can rest assured that createItem() is quite functional in 3.0.7.
