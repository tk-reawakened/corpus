### Levi · 2006-06-16 07:46 · #B328098

The loop he's refering to Quake is the while loop.

**Code:**

```
#while(done!==0)
```

And you can replace the internal menu with any number of premade menus systems or one of your own making. I usually prefer the use of plugins for custom systems like this, but that's me. Totally unnecessary.
Also I usually prefer the use of switch...case statements over the if statment for this kind of thing. Because the way you have it set up now it checks the button value against each possible value even after it has found the one it's looking for. Switch doesn't do this. Once a match is found it skips all other possiblities. Chances are you won't notice much if any speed difference but it is a lot less intense.
The use of Branch(:top) is totally unnecessary since you already have it looping constantly with the While loop. Just comment that out and you'll see no difference in how it runs.
One thing I did notice though that strikes me as odd is that you check for buttons that don't exist. Or at least they don't exist in this code you're presenting. You have a cursor map, but after running it you don't check any of its values. It seems utterly useless.
My suggestion is either replace the cursormap with buttons instead using the SetButton command. Or change res! to button! and remove the need to check for the mouse click.

### Levi · 2006-06-19 05:03 · #B328823

Actually Malegnis, he did close the switch statement. He just closed it too early.

**Code:**

```
      case(3)

      {

         internalmenu(0)

      }

      case(4)

      {

         #clearbuttons()

         #done!=1

        }

      }
```

Notice the extra "{" after "Case(4)". It closes the switch statement. However from there the while loop wasn't closed as Malegnis said. So you need to remove this extra close bracket and close the switch and while statements the way they're suppose to be closed.
As for the internal menus. You can create your own if you want to, though it is fairly difficult for a few things. Often menus such as Item menus require the addition of different variables before they work properly. So you may continue to use the internal menus or not. That's up to you.
