***Posting Bug Reports***
The BugBoard is one of the most useful hings on the whole site for me as a programmer. It helps mde to have a permanent record of past bugs. You all have the potential to add a little something to the Toolkit by finding and posting bugs. Most times a bug is posted, it is not something I have ever seen. I would never have found it without the help of others.
A Bug Report isn't much good to me if I cannot reproduce the error. If I can't reproduce it, then as far as I'm concerned, it's not a bug. As a consequence, you should follow these rules when you post a bug report...
Most of the time, bugs posted on the bug board turn out to be problems with the way a person is using the Toolkit (ie, wrong RPGCode, incorrect character setup, etc.) So, when you encounter something that you think is a bug, check the Toolkit help files to see if you are doing the right thing. Play the demo game. If the demo game does things properly on your system, then that means that you are just doing somehting wrong. If you can reproduce the bug and you are pretty sure that it is an actual bug, you can proceed onto step 2. If it's not a real bug, try asking for help on the General Message Board. **Make sure that the 'bug' is actually a bug and not a problem with your system! *Step 1:***
Once you are confident you have a bug, you can start to put together the bug report. Be as clear as possible. If I cannot reproduce it, I cannot fix it. **Try to reproduce the bug and write down *exactly* how you did it. *Step 2:***
There are two types of bug reports. A good type, and a really bad type. Here's an example of a really bad type: Hmm. How could I reproduce that bug? Well, let's try that again... **When you post a bug report, write as much info as you can. *Step 3:***
*When I go into a fight, the graphics get messed up. What kind of crappy program is this, anyway???*
* Bug name: fight refresh problem. Program: trans2.exe Description: When I start a fight with the #FightEnemy command (to fight one enemy), the fight starts up. I can run the fight ok, but once the fight ends, I use the reward program to #Send the player to a new board. Once the player is sent to a new board, I can move my player, but the graphics switch back to being the same graphics in the fight. It looks like the program is having problems refreshing the screen after I #Send from a fight. To Reproduce: 1) Start a fight with #FightEnemy 2) Make sure the enemy has a reward program that will send the player to a new board 3) After the fight has completed and you have been sent to the new board, move in any direction. The screen will not refresh properly. I am using version 2.10.
The second one was a good bug report, because I could reproduce it by following the steps outlined in the report. It may take a little more time to write a report like this, but it has a much better chance of being fixed. When you write a report, be clear. If any error messages pop up, write down what they are, don't just say 'some error message popped up'.
If anyone else sees the bug and can reporoduce it, they should write a reply to the message with CONFIRMED in the subject line. If all goes well, once I have the bug fixed, I will write FIXED in a reply to the bug report. Thanks for all your help in helping me find bugs in the program. Together we are making the Toolkit a more solid program.
