**someone set up us the bomb-- March 25, 2001**
Hey, everyone. Like I've said, I'm really busy these days and so I haven't been updating as much as I would like. But anyway... First off, I've got to commend all the efforts of the plugin developers of late. We're really starting to see what plugins can do, and even I am impressed at the stuff the Toolkit is doing these days under the influence of plugins. So, keep up the good work! That said, lately I've been trying my hand at a plugin of my own. Since there are beginning to be more plugins out there than the 5 slots avalable in the Toolkit, I'm writing something that should solve this problem. It's a plugin that will automatically load any other plugins sitting in the plugin directory and use them. It's like a mini plugin in manager in itself. And it'll be able to load dll files that aren't named like tkplugX.dll. Instead, any plugins loaded by my 'multiplug' plugin will be able to be named anything you like. So, you could have a plugin named TrueTypeFonts.dll, and if you were using my plugin, TrueTypeFonts.dll would automatically get loaded and used. I'll be open sourcing the plugin so that everyone can see how a complex plugin is developed. Anyway, just some stuff I've been playing around with. Unfortunately, 2.17 will probably be delayed a lot. While I'm here on my workterm, I'm using my roommate's computer, and he's moving away soon so I'll be without a system to work on. But that will only be for 3 weeks until I go home and I have my own system again. I'll likely still find a way to update the website, but I don't know how much development I'll be able to do. It's fristrating, but that's life. Cyrus wanted me to mention that he's got a radio show coming online called The Void. You can check it out at . That's all for now.
**say something, shout it from the rooftops of your head-- March 7, 2001**
Hi. Utterly disturbed by my lack of updates lately? Well, it's cos I am in the middle of a work term and I work most of the day, and don't have a lot of spare time. Anyway, I thought I'd share a few of my thoughts with everyone. I haven't touched 2.17 yet, but I'm starting to have some pretty cool ideas for it. Nothing really big, because there's not a whole lot of really big things the Toolkit needs. But I'd like to do some things I've been meaning to do for awhile: -Get rid of OLE automation. But you might say 'OLE is what lets the Toolkit play any media type, right? Well, that's right, except it causes a lot of problems too. If I remove it, I will create my own routines to emulate it, cos I trust my own code more than microsoft's. -Get rid of unnecissary ocx files. I have already killed off my own custom ocx files: dialog.ocx, dirbrowse.ocx and explore.ocx. 2.16 saw the final nail in that coffin when I replaced the file explorer with the new snazzy one it has. Now I'd like to get rid of some of the microsoft ocx's, like picclp32.ocx. Why? Well, the download will be smaller, there will be fewer runtime files to worry about, and it should make the Toolkit generally more stable. -I'd also like to do some real 'neato' stuff with the Toolkit, like internal night and day effects (I've been meaning to do that since day 1! And by the way, I've got some really *unique* ideas for that, too!), I definately want to get animated tiles working, and I'd really like to unify all animation in the Toolkit using just one format-- anm (from the Animation Editor). I'm talking about character animation, tile animation, *everything*. Wouldn't that be nice? -The RPGCode editor could use a going-over. Anyway, there's what I'd like to do for 2.17. As usual, I'm open to suggestions. I'd also like to apologise for all the email I've missed of late. Like I said, I've been very busy.

**a good overview of what's going on-- November 29, 2000**
I've been working lately at slimming down the download size for toolkit2.zip. At one point it had crept up as large as 4.6 MB (with 2.14, it is about 4.2, I think). But I'm hoping to keep the quality of the download the same (ie, the demo game is exactly the same-- I have merely migrated some things that took a lot of space (ie, the old .gph files) into newer files that take less space (like .tst)). Also, I removed the graphics from the help files. For those of you who already have the toolkit this will be no big deal as you already have downloaded all the graphis in the help files. Some other options include compiling trans2.exe in a different way-- did you know that trans2.exe can compile down to a size of 600KB? (Right now, trans2.exe is about 1.2 or 1.7 MB, I think). **maybe i just wanna breathe, maybe i just don't believe-- November 6, 2000**
Just thought I'd tell you all that 2.14 is very very close to being done. Expect it sometime this week or on the weekend. Some good news to relate: the plugin manager is almost entirely done. I don't know how many of you know anything about analysis of algorithms, but the old way of accessing special moves worked in O(n ) time. Now it's down to O(n) time (that means that if you had 100 moves before, loading the special move list is now 100x faster than before!) Before I fixed this, I tested loading a list of 50 moves-- it took almost 5 seconds! Now with the improved algorithm, it's so fast that the system tells me it takes 0 seconds. So it's much faster!
