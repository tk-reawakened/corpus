[argat: RPGCode to Lua transpiler](/thread/38/argat-rpgcode-lua-transpiler) Jul 25, 2016 16:41:12 GMT -5
Post by euix on Jul 25, 2016 16:41:12 GMT -5
Yeah, I want to ensure older games work with the new engine, as seemingly pointless as it is. The older games are the only content the engine has to show, but more importantly I would like to preserve the history for my own sake. The RPGCode parser is nearly complete; it can parse the entire 3.2.x demo game. I still need to parse class declarations, array expressions, conditional operator, member invocation operator (->), type hints, error handling syntax (on error ...) and a few little oddities from TK2. Following that it needs error recovery, a preprocessor for inclusions and directives (e.g. autolocal) and then it just needs to be unleashed on a bunch of existing games. Eventually I want to add a quirks mode to accept malformed programs that unfortunately still work in the current engine, but it's not a priority. Currently I am working on the compiler and virtual machine (Blade); I am working on the semantic analysis pass. After that's done I will move on to bytecode generation and the virtual machine, and then we'll have a fully functioning RPGCode toolchain. I am considering designing a new type-safe object-oriented scripting language (called Blade) to supplant RPGCode - I would only need to implement a parser and possibly a modified semantic analysis pass and the Blade compiler would handle the rest. Marz decided to use Lua on his own; I think we can do better but for now I am worrying about RPGCode. Eventually the Blade compiler will generate Java bytecode to take advantage of the JVM JIT, which is much easier than it sounds. That may make it into the first TK4 release, but I will work on completing the engine before I consider doing that.
